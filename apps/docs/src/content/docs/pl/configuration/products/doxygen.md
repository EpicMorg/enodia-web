title: Doxygen

Odczytuje, który Doxygen wygenerował witrynę z dokumentacją. Każda strona
HTML zapisana przez Doxygen to deklaruje — `<meta name="generator" content="Doxygen
1.19.0"/>`, `<!-- Generated by Doxygen 1.19.0 -->` oraz stopka — a sonda
pobiera wersję z dwóch pierwszych. Odczytywaną stroną jest `/`, chyba że
`path` celu stanowi inaczej. Domyślnym schematem jest `https`.

```yaml
targets:
  - id: api-docs
    product: doxygen
    address: https://docs.example.com
    path: /docs/        # opcjonalne, gdy witryna nie jest serwowana pod /
```

## Narzędzie do budowania, a nie serwer

Nie ma serwera Doxygen, o który można by zapytać: zapisywana wersja to ta,
którą dokumentacja została **ostatnio zbudowana** — i właśnie to ujawnia
zaniedbany potok budowania dokumentacji. Witryna z dokumentacją za SSO
(np. stroną logowania oauth2-proxy) nie pokazuje znacznika i kończy się
błędem jako nieobsługiwana; dla witryny za HTTP Basic należy
skonfigurować poświadczenie (poniżej).

## Uwierzytelnianie

Opcjonalne — tylko dla witryny za HTTP Basic. `basic` to jedyny
akceptowany rodzaj; od wersji 2.2.0 każdy inny rodzaj jest błędem
konfiguracji (zobacz
[Konfiguracja → Poświadczenia](/pl/configuration/#poświadczenia)).

```yaml
credentials:
  docs-basic:
    kind: basic
    username: reader
    password: "${DOCS_PASSWORD}"
```

## Rejestrowane pola

Tylko `version` — np. `1.19.0`; ta sonda nie zapisuje żadnych pól `extra`.

## Korelacja CVE

Dopasowywany do NVD, gdy skonfigurowano [blok `cve:`](/pl/cve/).

## Resolver cyklu życia

`github:doxygen/doxygen` — endoflife.date nie ma kalendarza dla Doxygen
(potwierdzone 404), więc zamiast tego jest rozwiązywany przez GitHub
Releases: wyłącznie najnowszy opublikowany tag niebędący wydaniem wstępnym
(prerelease), bez dat eol/support/lts (GitHub nie ma zdania na temat
polityki cyklu życia, zna tylko „najnowsze wydanie”). Doxygen oznacza
swoje wydania tagami `Release_1_18_0`; od wersji 2.2.0 resolver `github`
odczytuje taki zapis jako `1.18.0`.
