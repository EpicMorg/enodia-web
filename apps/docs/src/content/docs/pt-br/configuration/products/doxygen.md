---
title: Doxygen
description: Como configurar o enodia para sondar o Doxygen.
---

Lê qual Doxygen gerou um site de documentação. Toda página HTML que o
Doxygen escreve diz isso — `<meta name="generator" content="Doxygen
1.19.0"/>`, `<!-- Generated by Doxygen 1.19.0 -->` e o rodapé — e a sonda
obtém a versão dos dois primeiros. A página lida é `/`, a menos que o
`path` do alvo diga o contrário. O esquema padrão é `https`.

```yaml
targets:
  - id: api-docs
    product: doxygen
    address: https://docs.example.com
    path: /docs/        # opcional, quando o site não é servido em /
```

## Uma ferramenta de build, não um servidor

Não há um servidor Doxygen a consultar: a versão registrada é aquela com
que a documentação foi **gerada pela última vez** — e é exatamente isso
que denuncia um pipeline de documentação desatualizado. Um site de
documentação atrás de SSO (uma página de login do oauth2-proxy, por
exemplo) não mostra a marca e falha como não suportado; para um site
atrás de HTTP Basic, configure uma credencial (abaixo).

## Autenticação

Opcional — apenas para um site atrás de HTTP Basic. `basic` é o único
tipo aceito; desde a 2.2.0, qualquer outro tipo é um erro de configuração
(consulte [Configuração → Credenciais](/pt-br/configuration/#credenciais)).

```yaml
credentials:
  docs-basic:
    kind: basic
    username: reader
    password: "${DOCS_PASSWORD}"
```

## Campos registrados

Apenas `version` — por exemplo `1.19.0`; esta sonda não registra nenhum
campo `extra`.

## Correlação de CVEs

Correlacionado com o NVD quando um [bloco `cve:`](/pt-br/cve/) está configurado.

## Resolvedor de ciclo de vida

`github:doxygen/doxygen` — o endoflife.date não tem um calendário do
Doxygen (404 confirmado), então a resolução é feita pelos GitHub
Releases: apenas a tag publicada mais recente que não seja pré-lançamento,
sem datas de eol/support/lts (o GitHub não tem opinião sobre política de
ciclo de vida, apenas sobre "qual é o lançamento mais recente"). O
Doxygen marca os seus lançamentos como `Release_1_18_0`; desde a 2.2.0, o
resolvedor `github` lê essa grafia como `1.18.0`.
