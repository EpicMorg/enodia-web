Два запроса через Redfish: `GET /redfish/v1` — ради идентичности
вендора, затем `GET /redfish/v1/Managers/iDRAC.Embedded.1` — ради
версии прошивки.

```yaml
targets:
  - id: blade-1a-idrac
    product: dell-idrac
    address: https://idrac-blade-1a.example.com
    credentials: idrac-ro
```

## Аутентификация — обязательна

HTTP Basic auth; без неё эндпоинты отвечают `401` (подтверждено
вживую).

```yaml
credentials:
  idrac-ro:
    kind: basic
    username: enodia
    password: "${IDRAC_PASSWORD}"
```

Достаточно учётной записи iDRAC только для чтения. iDRAC обычно отдают
самоподписанный сертификат — закрепите его, а не отключайте проверку,
см. [Конфигурация → TLS](/ru/configuration/#tls-tls).

## Проверка личности вендора

Почему два запроса: подтверждено вживую на реальном iDRAC 12G — сам
ресурс менеджера вообще не несёт метки вендора, а корень сервиса
`/redfish/v1` несёт `Oem.Dell` (с сервисным тегом) и строку продукта
«Integrated Dell Remote Access Controller». Первый запрос подтверждает,
что это Dell, второй читает версию. `iDRAC.Embedded.1` — стандартный
идентификатор встроенного контроллера Dell, проверяется именно он.

Dell **CMC** (контроллер уровня шасси блейд-корзины) — другой продукт
вообще без Redfish-эндпоинта, и он не поддерживается.

## Записываемые поля

- `version` — `FirmwareVersion`, например `2.65.65.65`
- `extra.model`, если присутствует
- `extra.serviceTag`, если присутствует

## Сопоставление с CVE

Пока не сопоставляется — BMC-пробы появились в 2.1, и их сопоставление
с CVE в апстриме оставлено на отдельный, более поздний проход. См.
[Сопоставление с CVE](/ru/cve/#какие-продукты-сопоставляются).

## Резолвер жизненного цикла

Отсутствует — у прошивок BMC нет публичного календаря жизненного цикла
(подтверждено 404 под каждым опробованным слагом). Только
инвентаризация.
