Читает `GET /CHANGELOG` — файл журнала изменений, который DomainMOD
поставляет в корне веб-приложения и который отдаётся как статический
файл. Схема по умолчанию — `https`.

```yaml
targets:
  - id: domainmod-main
    product: domainmod
    address: https://domains.example.com
```

До DomainMOD, установленного в подкаталог (`DOMAINMOD_WEB_ROOT`),
проба добирается, если указать этот путь в адресе, например
`https://www.example.com/domainmod`.

## Почему CHANGELOG

DomainMOD показывает `Version 4.23.0` только в подвале интерфейса после
входа. CHANGELOG же доступен анонимно: он начинается с
`DomainMOD CHANGELOG`, затем идёт разделитель и самая новая запись
первой — `v4.23.0     2025-01-04`. Проба требует этот заголовок, чтобы
журнал изменений другого приложения не был принят за журнал DomainMOD.
Если веб-сервер блокирует файл, target считается неподдерживаемым.

## Аутентификация

Отсутствует — проба читает статический файл и не принимает ни одного
вида credential. Начиная с 2.2.0 credential, заданный для такого target,
не игнорируется молча, а считается ошибкой конфигурации; см.
[Конфигурация → Credentials](/ru/configuration/#credentials).

## Записываемые поля

Только `version` — например, `4.23.0`, из самой новой записи
CHANGELOG `v4.23.0     2025-01-04` (подтверждено вживую на
`domainmod/domainmod:latest`, чей `software.inc.php` содержит
`SOFTWARE_VERSION = '4.23.0'`). Полей `extra` эта проба не записывает.

## Сопоставление с CVE

Сверяется с NVD, если настроен [блок `cve:`](/ru/cve/).

## Резолвер жизненного цикла

`github:domainmod/domainmod` — у endoflife.date нет календаря для DomainMOD
(подтверждено 404), поэтому резолвинг идёт через GitHub Releases:
только последний опубликованный, не pre-release тег, без данных по
eol/support/lts (у GitHub нет мнения о политике жизненного цикла,
только «какой релиз последний»).
