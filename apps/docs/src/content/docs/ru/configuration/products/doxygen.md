Определяет, какой Doxygen сгенерировал сайт документации. Каждая
HTML-страница, которую пишет Doxygen, сообщает об этом —
`<meta name="generator" content="Doxygen 1.19.0"/>`,
`<!-- Generated by Doxygen 1.19.0 -->` и футер, — и проба берёт версию
из первых двух. Читается страница `/`, если `path` таргета не указывает
другую. Схема по умолчанию — `https`.

```yaml
targets:
  - id: api-docs
    product: doxygen
    address: https://docs.example.com
    path: /docs/        # опционально, если сайт отдаётся не с /
```

## Инструмент сборки, а не сервер

Опрашивать здесь нечего — сервера Doxygen нет: записывается версия, которой
документация была **собрана в последний раз**, — именно это и выявляет
устаревший конвейер сборки документации. Сайт документации за SSO
(например, за страницей входа oauth2-proxy) не содержит отметки и
завершается ошибкой «не поддерживается»; для сайта за HTTP Basic
настройте credential (см. ниже).

## Аутентификация

Опционально — только для сайта за HTTP Basic. Принимается единственный
вид — `basic`; начиная с 2.2.0 любой другой вид — ошибка конфигурации
(см. [Конфигурация → Credentials](/ru/configuration/#credentials)).

```yaml
credentials:
  docs-basic:
    kind: basic
    username: reader
    password: "${DOCS_PASSWORD}"
```

## Записываемые поля

Только `version` — например `1.19.0`; эта проба не записывает никаких
полей `extra`.

## Сопоставление с CVE

Сверяется с NVD, если настроен [блок `cve:`](/ru/cve/).

## Резолвер жизненного цикла

`github:doxygen/doxygen` — у endoflife.date нет календаря для Doxygen
(подтверждено 404), поэтому резолвинг идёт через GitHub Releases:
только последний опубликованный, не pre-release тег, без данных по
eol/support/lts (у GitHub нет мнения о политике жизненного цикла,
только «какой релиз последний»).
Doxygen помечает релизы тегами вида `Release_1_18_0`; начиная с 2.2.0
резолвер `github` читает такое написание как `1.18.0`.
