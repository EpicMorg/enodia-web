Читает `GET /ghost/api/admin/site/` — единственный эндпоинт Admin API,
который Ghost отдаёт без сессии и ключа (админка читает его ещё до
входа), — и берёт `site.version`. Схема по умолчанию — `https`.

```yaml
targets:
  - id: ghost-main
    product: ghost
    address: https://blog.example.com
```

## Публичны только major.minor

Подтверждено вживую на `ghost:6`: эндпоинт вернул `6.69` — то же, что
`<meta name="generator">` и заголовок `Content-Version`, — хотя
установленный пакет был 6.69.0. Полная версия закрыта ключом Admin API,
подписанным JWT, — новый вид credential ради одной цифры того не стоит:
релизы Ghost почти без исключений имеют вид `x.y.0`, а `6.69` при
сравнении равно тегу `v6.69.0`.

## Аутентификация

Отсутствует — эндпоинт публичный, и проба не принимает ни одного вида credential.
Начиная с 2.2.0 credential, привязанный к таргету `ghost`, — это ошибка
конфигурации, а не молча игнорируемая настройка; см.
[Конфигурация → Credentials](/ru/configuration/#credentials).

## Записываемые поля

Только `version` — major.minor, например `6.69`; эта проба не записывает
никаких полей `extra`.

## Сопоставление с CVE

Сверяется с NVD и БДУ ФСТЭК, если настроен [блок `cve:`](/ru/cve/).

## Резолвер жизненного цикла

`github:TryGhost/Ghost` — у endoflife.date нет календаря для Ghost
(подтверждено 404), поэтому резолвинг идёт через GitHub Releases:
только последний опубликованный, не pre-release тег, без данных по
eol/support/lts (у GitHub нет мнения о политике жизненного цикла,
только «какой релиз последний»).
