Читает `GET /redfish/v1/Managers/1/` — со слешем в конце, и подтверждено
вживую, что это важно, — ради версии прошивки контроллера.

```yaml
targets:
  - id: vm43-ilo
    product: hp-ilo4
    address: https://ilo-vm43.example.com
    credentials: ilo-ro
```

## Аутентификация — обязательна

HTTP Basic auth; без неё эндпоинт отвечает `401` (подтверждено вживую).

```yaml
credentials:
  ilo-ro:
    kind: basic
    username: enodia
    password: "${ILO_PASSWORD}"
```

Достаточно учётной записи iLO только для чтения. iLO обычно отдают
самоподписанный сертификат — закрепите его, а не отключайте проверку,
см. [Конфигурация → TLS](/ru/configuration/#tls-tls).

## Только iLO 4

API iLO 4 называет себя «HP RESTful Root Service» — это API HP,
появившийся раньше Redfish, а не реализация Redfish, — но именно этот
ресурс совпадает с Redfish достаточно близко, чтобы читаться так же.
Идентичность проверяется по ключу `Oem.Hp`. iLO 5 полностью совместим с
Redfish и, скорее всего, требует другой проверки; iLO 5, чтобы
подтвердить это вживую, не было, поэтому пробы для него пока нет, а не
есть угаданная.

## Записываемые поля

- `version` — разобранная из `FirmwareVersion`: `iLO 4 v2.82` → `2.82`
- `extra.raw` — полная строка `FirmwareVersion`

## Сопоставление с CVE

Сверяется с NVD и БДУ ФСТЭК, если настроен [блок `cve:`](/ru/cve/). Начиная с 2.2; версия прошивки
из пробы (`2.82`) сравнивается как есть с диапазонами NVD
`integrated_lights-out_4` и записями БДУ «HP iLO 4».

## Резолвер жизненного цикла

Отсутствует — у прошивок BMC нет публичного календаря жизненного цикла
(подтверждено 404 под каждым опробованным слагом). Только
инвентаризация.
