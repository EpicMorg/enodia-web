Читает версию из **заголовка ответа `X-Jenkins`**, а не из тела ответа —
Jenkins выставляет этот заголовок на каждый ответ, включая `403` на
неаутентифицированный запрос, тогда как тело, которое возвращает
аутентифицированный запрос, вообще не содержит поля версии.

```yaml
targets:
  - id: jenkins-main
    product: jenkins
    address: https://jenkins.example.com
```

## Аутентификация

Опционально. Свежий инстанс со стандартной security-схемой отвечает на
`/api/json` с кодом `403` на анонимный запрос — здесь это не ошибка,
`X-Jenkins` всё равно проставлен в том же самом ответе. Basic auth
принимается, если вы всё же хотите аутентифицироваться:

```yaml
credentials:
  jenkins-admin:
    kind: basic
    username: admin
    password: "${JENKINS_TOKEN}"
```

## Записываемые поля

- `version` — из заголовка `X-Jenkins`
- `extra.mode`, `extra.useSecurity` — заполняются, только если запрос
  прошёл аутентификацию настолько, чтобы получить тело `200`; при
  анонимном `403` отсутствуют

## Резолвер жизненного цикла

`endoflife:jenkins`.
