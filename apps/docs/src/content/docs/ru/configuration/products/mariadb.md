Сырой TCP-протокол, не HTTP — `address` задаётся как `host` или
`host:port`, без схемы. Порт по умолчанию — `3306`. Тот же handshake,
что и у [MySQL](/ru/configuration/products/mysql/): MariaDB сама
сообщает версию в первом пакете handshake, ещё до какой-либо
аутентификации, поэтому этой пробе credentials не нужны вообще.

```yaml
targets:
  - id: mariadb-main
    product: mariadb
    address: db.example.com:3306
```

## Аутентификация

Отсутствует — версия читается прямо из handshake.

## Проверка личности вендора

MariaDB и MySQL говорят на одном и том же handshake и различаются только
строкой версии, у которой два вида, оба подтверждены вживую:

- **MariaDB 10.x** маскирует версию префиксом совместимости `5.5.5-` для
  старых MySQL-клиентов: `5.5.5-10.11.19-MariaDB-ubu2204`. Маска
  снимается.
- **MariaDB 11.0+** от маски отказалась: `11.4.13-MariaDB-ubu2404`,
  `12.3.3-MariaDB-ubu2404`. Тогда единственный признак — `-MariaDB` в
  версии. Распознаётся начиная с 2.1.1 — 2.1.0 такие серверы отклоняла.

Принимается любой из двух видов. Указанная на настоящий сервер MySQL, в
версии которого нет ни того ни другого, проба откажет, а не запишет
неверный факт; это зеркальное отражение того, как
[`mysql`](/ru/configuration/products/mysql/#mariadb--другой-продукт)
отказывает серверу MariaDB.

## Записываемые поля

- `version` — числовая версия, например `10.11.19`
- `extra.tag` — тег вендора после неё, например `MariaDB-ubu2204`, если
  присутствует

## Сопоставление с CVE

Сверяется с NVD и БДУ ФСТЭК, если настроен [блок `cve:`](/ru/cve/), а с `cve.mariadb.path` — ещё и с собственной таблицей исправленных CVE MariaDB, вердикт которой по сериям важнее открытых диапазонов БДУ и NVD. См. [MariaDB: собственная таблица вендора](/ru/cve/#mariadb-собственная-таблица-вендора).
