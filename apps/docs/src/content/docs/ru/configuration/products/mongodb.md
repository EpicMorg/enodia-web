Проба на сыром wire-протоколе, не HTTP — `address` это `host` или
`host:port`, без схемы. Порт по умолчанию — `27017`, если не указан.
Выполняет команду `buildInfo` через wire-протокол (`OP_MSG`) и читает
поле `version` — без клиентской библиотеки, без запроса в стиле
`SELECT`.

```yaml
targets:
  - id: mongodb-main
    product: mongodb
    address: db.example.com:27017
```

## Аутентификация

Отсутствует — `buildInfo` входит в небольшой набор команд, на которые
MongoDB всегда отвечает ещё до аутентификации. Подтверждено вживую на
двух реальных контейнерах `mongo:7`: один вообще без контроля доступа,
другой с включённым `--auth` и настроенным root-пользователем — оба
вернули идентичный полный документ `buildInfo` вообще без отправки
credentials.

## Записываемые поля

- `version`
- `extra.enterprise` — `"true"`, если в `modules` из `buildInfo` есть
  `enterprise`, иначе `"false"` (у community-сервера это пустой массив);
  не записывается, если поля нет

## Сопоставление с CVE

Сверяется с NVD и БДУ ФСТЭК, если настроен [блок `cve:`](/ru/cve/). С учётом редакции: проба записывает редакцию сервера в `extra.enterprise`, и community-инстанс не видит находок только для enterprise. Если редакция неизвестна, сохраняются все находки.

## Резолвер жизненного цикла

`endoflife:mongodb`.
