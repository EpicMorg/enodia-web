Читает `GET /api/version` для получения версии — намеренно
неверсионированный путь, а не конкретный `/api/v11/version`. Perforce
не раз сдвигал минимально поддерживаемую версию этого API (Swarm 2017.3
понимает только v7, 2018.2 — уже v9), а запрос вне допустимого диапазона
`vN` получает `401` на в остальном полностью анонимном эндпоинте.
Неверсионированная форма избавляет от необходимости угадывать, какой
именно `vN` ещё принимает конкретная установка.

```yaml
targets:
  - id: swarm-main
    product: perforce-swarm
    address: https://swarm.example.com
```

## Аутентификация

Отсутствует — эндпоинт не принимает никакого credential.

## Разбор версии

Необработанное поле выглядит как `SWARM/2024.6/2710109 (2025/01/28)` —
оно разбирается на обычную версию (`2024.6`), номер changelist и дату
релиза. Нераспознанный формат оставляет необработанную строку как
`version`, вместо того чтобы завершиться ошибкой — это всё равно факт,
который сообщил сервер.

## Записываемые поля

- `version` — например, `2024.6`
- `extra.raw` — полная неразобранная строка
- `extra.changelist`, `extra.releaseDate` — только если формат
  распознан

## Резолвер жизненного цикла

Отсутствует — у endoflife.date нет календаря ни под `perforce-swarm`,
ни под `helix-swarm`, `swarm` или `perforce` (все подтверждённо отдают
404). Пока только инвентаризация.
