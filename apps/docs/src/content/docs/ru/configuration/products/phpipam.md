Читает страницу входа, `GET /index.php?page=login`, анонимно. Схема по
умолчанию — `https`.

```yaml
targets:
  - id: ipam-main
    product: phpipam
    address: https://ipam.example.com
```

## Откуда берётся версия

В подвале страницы входа написано `phpIPAM IP address management [v1.8.3]`,
а все стили и скрипты на ней подключаются с `?v=1.8.3_r002_v46` —
собственным префиксом скриптов phpIPAM: видимая версия, ревизия кода и
версия схемы базы данных. Версия берётся из подвала; суффикс ресурсов —
запасной вариант, если подвал изменён, и источник ревизии и версии
схемы. Более старые релизы подключают ресурсы с голым `?v=1.7.3`
(замечено на рабочем экземпляре 1.7.3), без ревизии и схемы — версия
всё равно читается, а двух полей `extra` тогда нет. Страница без
того и другого считается неподдерживаемой.

## Аутентификация

Отсутствует — проба читает анонимную страницу и не принимает ни одного
вида credential. Начиная с 2.2.0 credential, заданный для такого target,
не игнорируется молча, а считается ошибкой конфигурации; см.
[Конфигурация → Credentials](/ru/configuration/#credentials).

## Записываемые поля

- `version` — например, `1.8.3`, из `phpIPAM IP address management [v1.8.3]`
  (подтверждено вживую на `phpipam/phpipam-www:latest`)
- `extra.revision` — ревизия кода из суффикса ресурсов, например `002`
- `extra.dbVersion` — версия схемы базы данных из суффикса ресурсов,
  например `46`

## Сопоставление с CVE

Сверяется с NVD и БДУ ФСТЭК, если настроен [блок `cve:`](/ru/cve/).

## Резолвер жизненного цикла

`github:phpipam/phpipam` — у endoflife.date нет календаря для phpIPAM
(подтверждено 404), поэтому резолвинг идёт через GitHub Releases:
только последний опубликованный, не pre-release тег, без данных по
eol/support/lts (у GitHub нет мнения о политике жизненного цикла,
только «какой релиз последний»).
