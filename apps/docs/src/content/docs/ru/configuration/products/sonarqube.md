Читает `GET /api/system/status` для получения версии — один и тот же
эндпоинт независимо от того, какой именно SonarQube у вас на самом деле
работает (см. ниже).

```yaml
targets:
  - id: sonarqube-main
    product: sonarqube
    address: https://sonarqube.example.com
```

## Аутентификация

Отсутствует — этот эндпоинт (наравне с `/api/server/version` и
`/api/system/ping`) остаётся доступным без credentials даже после
включения глобальной настройки SonarQube «Force user authentication».
SonarQube считает его маршрутом для проверки живости, к которому
балансировщику нагрузки нужен доступ без входа, а не обычным защищённым
API.

## SonarQube Server и SonarQube Community Build

В конце 2024 года SonarSource разделили «SonarQube» на два продукта:
**SonarQube Server** (прямое продолжение всех прежних редакций
Community/Developer/Enterprise/Data Center, по-прежнему версионируется
по календарю — `2025.1`, `2026.4`, ...) и **SonarQube Community Build**
(новая, отдельная, всегда бесплатная сборка с собственным, более
быстрым циклом выпуска, версии вида `24.12`, `25.12`, `26.9`, ... — та
же календарная схема, только год двузначный, а не четырёхзначный).
endoflife.date отслеживает их как две отдельные страницы с по-настоящему
разными данными о циклах — `product: sonarqube` не требует второй
записи в конфиге, чтобы их различить: какой из двух вариантов
применяется, надёжно читается из самой строки версии, которую
`sonarqubeProbe` и так получает:

- Четырёхзначный год в начале (`2025.x`, `2026.x`) → **SonarQube
  Server**.
- Двузначный, начиная с `24` (`24.x`, `25.x`, `26.x`) → **SonarQube
  Community Build**.
- Всё меньшее (голый мажор до разделения, например `9.9.8.100196`,
  `10.7.0.96327`) — трактуется как Community Build, поскольку у обеих
  страниц идентичная история для версий до разделения.

## Записываемые поля

- `version`
- `extra.id`
- `extra.status` — одно из `UP`, `DOWN`, `STARTING`, `RESTARTING`,
  `DB_MIGRATION_NEEDED`, `DB_MIGRATION_RUNNING`; факт о состоянии
  сервера, записываемый как есть, а не превращаемый в ошибку, если он
  не `UP`

## Резолвер жизненного цикла

Выбирается для каждого наблюдения отдельно, а не зафиксирован:
`endoflife:sonarqube-server` либо `endoflife:sonarqube-community`,
определяется по строке версии, как описано выше. Собственный список
`enodia products` (который выполняется, когда ещё ничего не опрошено)
показывает `endoflife:sonarqube-server` как статический резолвер по
умолчанию — это лишь то, что печатается до того, как реально проверен
хоть один таргет, а не то, к чему обязательно резолвится каждое
наблюдение.
