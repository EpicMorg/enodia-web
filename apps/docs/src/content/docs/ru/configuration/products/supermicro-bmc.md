Читает `GET /redfish/v1/Managers/1` — собственный Redfish-ресурс
менеджера BMC — ради версии прошивки.

```yaml
targets:
  - id: srv125-bmc
    product: supermicro-bmc
    address: https://bmc-srv125.example.com
    credentials: bmc-admin
```

## Аутентификация — обязательна

HTTP Basic auth; без неё эндпоинт отвечает `401` (подтверждено вживую).

```yaml
credentials:
  bmc-admin:
    kind: basic
    username: ADMIN
    password: "${BMC_PASSWORD}"
```

Достаточно учётной записи BMC только для чтения. BMC обычно отдают
самоподписанный сертификат — закрепите его, а не отключайте проверку,
см. [Конфигурация → TLS](/ru/configuration/#tls-tls).

## Проверка личности вендора

Подтверждено вживую на двух поколениях — плате серии X12 (AST2600,
прошивка `01.05.25`) и более старой эпохи X9/X10 (прошивка
`01.73.13`). Ни у одной нет поля производителя, до которого проба могла
бы дотянуться за один запрос, но у обеих на этом самом ресурсе есть ключ
`Oem.Supermicro` — его и проверяет проба. BMC другого вендора, ответивший
по тому же пути, вызовет отказ, а не запись как Supermicro.

## Записываемые поля

- `version` — `FirmwareVersion`, например `01.05.25`
- `extra.model`, если присутствует

## Сопоставление с CVE

Пока не сопоставляется — BMC-пробы появились в 2.1, и их сопоставление
с CVE в апстриме оставлено на отдельный, более поздний проход. См.
[Сопоставление с CVE](/ru/cve/#какие-продукты-сопоставляются).

## Резолвер жизненного цикла

Отсутствует — у прошивок BMC нет публичного календаря жизненного цикла
(подтверждено 404 под каждым опробованным слагом). Только
инвентаризация.
