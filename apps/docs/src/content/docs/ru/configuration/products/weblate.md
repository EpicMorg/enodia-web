Читает `GET /about/` анонимно. Схема по умолчанию — `https`.

```yaml
targets:
  - id: weblate-main
    product: weblate
    address: https://weblate.example.com
```

## Откуда берётся версия

В подвале каждой страницы Weblate написано `Powered by <a href="https://weblate.org/">Weblate 2026.10</a>`,
а ссылка Documentation ведёт на `docs.weblate.org/en/weblate-2026.10/`.
Проба читает сначала подвал, а если он изменён — ссылку на документацию;
страница без того и другого считается неподдерживаемой. Читается
`/about/`, потому что эта страница есть в любом Weblate; сайт с
`REQUIRE_LOGIN` перенаправляет её на страницу входа, у которой тот же
подвал. Корень REST API (`/api/`) тоже анонимен, но версии не содержит,
а `/api/metrics/` требует токен.

После 5.x Weblate перешёл на календарные версии (`2026.9`, `2026.9.1`,
`2026.10`); разбираются оба формата.

## Аутентификация

Отсутствует — проба читает анонимную страницу и не принимает ни одного
вида credential. Начиная с 2.2.0 credential, заданный для такого target,
не игнорируется молча, а считается ошибкой конфигурации; см.
[Конфигурация → Credentials](/ru/configuration/#credentials).

## Записываемые поля

Только `version` — например, `2026.10` (подтверждено вживую на
`weblate/weblate:latest`). Полей `extra` эта проба не записывает.

## Сопоставление с CVE

Сверяется с NVD, если настроен [блок `cve:`](/ru/cve/).

## Резолвер жизненного цикла

`github:WeblateOrg/weblate` — у endoflife.date нет календаря для Weblate
(подтверждено 404), поэтому резолвинг идёт через GitHub Releases:
только последний опубликованный, не pre-release тег, без данных по
eol/support/lts (у GitHub нет мнения о политике жизненного цикла,
только «какой релиз последний»).
Weblate тегирует свои релизы как `weblate-2026.10`; начиная с 2.2.0
резолвер отбрасывает ведущий `<repo>-` или `<repo>_` в тегах релизов,
поэтому в LATEST и CYCLE читается `2026.10`.
