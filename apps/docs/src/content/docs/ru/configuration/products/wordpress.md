Пробует две анонимные поверхности по очереди и использует ту, что
ответит первой:

1. Собственную строку `<generator>` RSS-ленты (`/?feed=rss2` — форма
   через query-строку, работающая независимо от того, настроены ли
   «красивые» постоянные ссылки).
2. Тег `<meta name="generator" content="WordPress X.Y.Z" />` на
   домашней странице (`/`).

```yaml
targets:
  - id: wordpress-main
    product: wordpress
    address: https://blog.example.com
```

## Аутентификация

Отсутствует — эндпоинт не принимает никакого credential.

## Почему сначала пробуется лента

Лента переживает самый распространённый шаг hardening: WordPress
регистрирует свой тег generator на хуках ленты отдельно от собственного
действия `wp_head` для домашней страницы, поэтому однострочный сниппет
`remove_action('wp_head', 'wp_generator')` из любого туториала «скрой
версию WordPress» убирает только тег на домашней странице, а не в
ленте — подтверждено чтением собственных регистраций хуков WordPress, а
не предположением. Сайт, который пошёл дальше и полностью отключил
ленты или убрал оба сигнала, попадает в понятную ошибку «не
поддерживается».

## Записываемые поля

Только `version` — эта проба не записывает никаких полей `extra`.

## Резолвер жизненного цикла

`endoflife:wordpress`.
