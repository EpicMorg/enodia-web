---
title: Zou
description: Настройка enodia для опроса Zou (API-бэкенд CG-Wire).
---

Читает `GET /api/status` для получения версии — реальный API-бэкенд за
стеком трекинга производства от CG-Wire, известным по бренду
[Kitsu](/ru/configuration/products/kitsu/), его Vue.js-фронтенду, у
которого нет собственного эндпоинта версии.

```yaml
targets:
  - id: zou-main
    product: zou
    address: https://kitsu.example.com
```

## Аутентификация

Отсутствует — эндпоинт не принимает никакого credential.

## Проверка личности вендора

Поле `name` из ответа сверяется со строкой `"Zou"` — та же логика, что
и у проб Atlassian и Jellyfin: явное указание продукта в конфиге должно
ловить адрес, указывающий не на тот сервис.

## `zou` и `kitsu` — одна проба, разные резолверы, не алиас

`product: kitsu` обращается к тому же самому эндпоинту и той же
реализации пробы — почему они зарегистрированы как отдельные продукты,
а не один продукт с алиасом, см. на
[его собственной странице](/ru/configuration/products/kitsu/): у
собственного репозитория `zou` на GitHub нет пригодных для использования
Releases (только голые git-теги, подтверждено вживую), поэтому
`product: zou` остаётся без резолвера, вместо того чтобы рисковать
сравнением с версией не того компонента.

## Записываемые поля

- `version`
- `extra.databaseUp`, `extra.keyValueStoreUp`, `extra.eventStreamUp`,
  `extra.jobQueueUp`, `extra.indexerUp` — флаги состояния компонентов,
  `"true"`/`"false"`

## Резолвер жизненного цикла

Отсутствует — у репозитория `cgwire/zou` на GitHub нет пригодных для
резолвинга Releases (подтверждено вживую — его Releases API возвращает
пустой список, только голые git-теги). Если вы воспринимаете свою
установку как «работающую на Kitsu», а не «на Zou», `product: kitsu`
даст реальный резолвер против `cgwire/kitsu`, указывая при этом ровно
на тот же самый бэкенд.
