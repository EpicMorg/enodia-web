«Kitsu» — общеизвестное название стека для трекинга производства от
CG-Wire, но сам Kitsu — это Vue.js-фронтенд без собственного эндпоинта
версии. На `GET /api/status` — подтверждено вживую, в том числе на
хосте, буквально названном «kitsu» в DNS, — отвечает на самом деле
**Zou**, API-бэкенд, с которым общается Kitsu. `product: kitsu`
принимается как алиас для тех, кто обращается по названию, под которым
знает стек; оба варианта ведут к одной и той же пробе.

```yaml
targets:
  - id: kitsu-main
    product: zou   # или: kitsu
    address: https://kitsu.example.com
```

## Аутентификация

Отсутствует — эндпоинт не принимает никакого credential.

## Проверка личности вендора

Поле `name` из ответа сверяется со строкой `"Zou"` — та же логика, что
и у проб Atlassian и Jellyfin: явное указание продукта в конфиге должно
ловить адрес, указывающий не на тот сервис.

## Записываемые поля

- `version`
- `extra.databaseUp`, `extra.keyValueStoreUp`, `extra.eventStreamUp`,
  `extra.jobQueueUp`, `extra.indexerUp` — флаги состояния компонентов,
  `"true"`/`"false"`

## Резолвер жизненного цикла

Отсутствует — у endoflife.date нет календаря ни под `zou`, ни под
`kitsu` или `cg-wire` (все подтверждённо отдают 404). Пока только
инвентаризация.
