Лише для самостійно розгорнутих серверів — немає сенсу спрямовувати це на
власний хмарний сервіс Bitwarden. Читає `GET /api/version`, який повертає
голий JSON-рядок (а не обʼєкт). Облікові дані не потрібні: клієнтські
застосунки використовують цей ендпоінт, щоб перевірити сумісність із
сервером ще до входу.

```yaml
targets:
  - id: bitwarden-main
    product: bitwarden
    address: https://vault.example.com
```

## Автентифікація

Немає — ендпоінт не приймає жодного виду облікових даних.

## Не той самий продукт, що Vaultwarden

[Vaultwarden](/uk/configuration/products/vaultwarden/) — це написана з нуля
на Rust реімплементація API сервера Bitwarden, а не форк, із власною
незалежною нумерацією версій. Він надає ідентичний ендпоінт і формат
відповіді, але зареєстрований як окремий `product:` — якщо вказати для
інсталяції Vaultwarden `product: bitwarden`, версію одного проєкту буде
порівняно з історією релізів іншого.

## Зіставлення з CVE

Зіставляється з NVD, якщо налаштовано [блок `cve:`](/uk/cve/).

## Резолвер життєвого циклу

`github:bitwarden/server` — endoflife.date не має календаря `bitwarden`
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»).
