Читає `GET /login` анонімно. Схема за замовчуванням — `https`. Сторінка
входу містить `<meta id="coder-options" data-settings="{...}">` —
екранований для HTML JSON, — і його `codeServerVersion` є версією
сервера; проба знімає екранування з атрибута й декодує його.

```yaml
targets:
  - id: code-main
    product: code-server
    address: https://code.example.com
```

## Чому сторінка входу

Власний `/version` у code-server вимагає пароля, а `/healthz` не містить
версії. Сторінка входу доступна без входу в систему й містить ті самі
параметри, з якими запускається редактор. Сторінка без елемента
`coder-options` позначається як «не підтримується» (це не code-server).

## Автентифікація

Немає — проба читає анонімну сторінку й не приймає жодного виду облікових
даних. Починаючи з 2.2.0, облікові дані, налаштовані для цієї цілі, є
помилкою конфігурації, а не ігноруються; див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## Записувані поля

Лише `version` — напр. `4.141.0` (підтверджено наживо на
`codercom/code-server:latest`, чий `code-server --version` повідомив 4.141.0
з Code 1.141.0). Ця проба не записує полів `extra`.

## Зіставлення з CVE

Зіставляється з NVD, якщо налаштовано [блок `cve:`](/uk/cve/).

## Резолвер життєвого циклу

`github:coder/code-server` — endoflife.date не має календаря code-server
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»).
