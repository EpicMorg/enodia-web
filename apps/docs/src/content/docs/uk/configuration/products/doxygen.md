Визначає, яким Doxygen згенеровано сайт документації. Кожна HTML-сторінка,
яку пише Doxygen, повідомляє про це — `<meta name="generator" content="Doxygen
1.19.0"/>`, `<!-- Generated by Doxygen 1.19.0 -->` і нижній колонтитул, — і
проба бере версію з перших двох. Читається сторінка `/`, якщо `path` цілі
не вказує інше. Схема за замовчуванням — `https`.

```yaml
targets:
  - id: api-docs
    product: doxygen
    address: https://docs.example.com
    path: /docs/        # необовʼязково, якщо сайт віддається не з /
```

## Інструмент збирання, а не сервер

Сервера Doxygen, якого можна було б запитати, немає: записана версія — це
та, якою документацію було **зібрано востаннє**, — саме це й виявляє
застарілий конвеєр документації. Сайт документації за SSO (скажімо,
сторінкою входу oauth2-proxy) не показує позначки й завершується помилкою
як непідтримуваний; для сайту за HTTP Basic налаштуйте облікові дані
(нижче).

## Автентифікація

Необовʼязкова — лише для сайту за HTTP Basic. `basic` — єдиний вид, що
приймається; починаючи з 2.2.0, будь-який інший вид є помилкою
конфігурації (див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані)).

```yaml
credentials:
  docs-basic:
    kind: basic
    username: reader
    password: "${DOCS_PASSWORD}"
```

## Записувані поля

Лише `version` — напр. `1.19.0`; ця проба не записує полів `extra`.

## Зіставлення з CVE

Зіставляється з NVD, якщо налаштовано [блок `cve:`](/uk/cve/).

## Резолвер життєвого циклу

`github:doxygen/doxygen` — endoflife.date не має календаря Doxygen
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»). Doxygen позначає свої релізи тегами
`Release_1_18_0`; починаючи з 2.2.0, резолвер `github` читає таке написання
як `1.18.0`.
