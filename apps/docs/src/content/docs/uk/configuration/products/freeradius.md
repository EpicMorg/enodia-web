SSH-проба: вона входить на хост і запускає власний `-v` сервера. Якщо
порт не вказано, використовується `22`, без схеми — той самий механізм
SSH, облікові дані та перевірка ключа хоста, що й у сімейства
[ідентифікації ОС через SSH](/uk/configuration/products/ssh-os-probes/).

```yaml
targets:
  - id: radius-01
    product: freeradius
    address: radius-01.example.com
    credentials: linux-host-ssh
```

## Чому SSH

RADIUS не має обміну версіями, як і відповідь Status-Server у FreeRADIUS —
її словники визначають лічильники статистики, а не атрибут версії. Тож
версію можна отримати лише від самого бінарного файлу сервера. Проба
пробує `freeradius` (Debian/Ubuntu) і `radiusd` (сімейство RHEL, збірки з
вихідного коду) — спершу за назвою, потім за шляхом у `/usr/sbin`,
оскільки `PATH` сеансу SSH без входу в систему часто не містить
`/usr/sbin`.

## Автентифікація — обовʼязкова

Облікові дані SSH, `ssh-key` або `password` — див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## FreeRADIUS у контейнері

Якщо FreeRADIUS працює в Docker або Podman, а на самому хості бінарного
файлу немає, вкажіть контейнер в `options` — тоді команда виконується
через `docker exec` (або `podman exec`):

```yaml
targets:
  - id: radius-01
    product: freeradius
    address: radius-01.example.com
    credentials: linux-host-ssh
    options:
      container: freeradius          # назва контейнера
      container_runtime: podman      # необовʼязково: docker (за замовчуванням) або podman
```

Користувачеві SSH має бути дозволено використовувати це середовище
виконання. Назва контейнера перевіряється за власним шаблоном назв
Docker, перш ніж потрапити у віддалену команду.

## Записувані поля

- `version` — напр. `3.2.10`, з `FreeRADIUS Version 3.2.10 (git #9071ea041)`
- `extra.git` — git-хеш збірки, якщо є
- `extra.container` — назва контейнера, якщо задано `options.container`
- `extra.hostKeyVerified`

## Зіставлення з CVE

Зіставляється з NVD і БДУ ФСТЕК, якщо налаштовано [блок `cve:`](/uk/cve/).
Обидва джерела враховуються так, як їх опубліковано: діапазон NVD для
BlastRADIUS (CVE-2024-3596) охоплює лише версії до 3.0.27 і нічого не
містить для гілки 3.2 (виправлено в 3.2.5), тож хост 3.2.3 не отримує
для неї знахідки.

## Резолвер життєвого циклу

`github-tag-branches:FreeRADIUS/freeradius-server`. endoflife.date не має
сторінки FreeRADIUS (підтверджено 404), а FreeRADIUS підтримує 3.0.x і
3.2.x паралельно, позначаючи релізи тегами на кшталт `release_3_2_10`.
Цей тип резолвера читає теги як **один цикл підтримки на кожну
гілку major.minor**, кожна зі своїм останнім тегом, тож повністю
пропатчена 3.0.28 показується як `current` у своїй гілці з доступною
новішою гілкою, а не як «відстає від 3.2.10». Читається лише максимальна
сторінка GitHub зі 100 тегів; як і інші резолвери GitHub, він не містить
дат EOL, а `GITHUB_TOKEN` підвищує його ліміт запитів (див.
[Підтримувані продукти](/uk/products/)).
