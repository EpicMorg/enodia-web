Запасний вихід для всього, що не має окремої проби, — написаний вручну
блок `parser:` замість вкомпільованої логіки на Go. Повний довідник полів,
зафіксований словник `json`/`xml`/`header`/`plaintext`/`regex` і примітка
щодо написання поля `clean_regex` містяться в
[Конфігурація → Проба generic](/uk/configuration/#проба-generic);
ця сторінка існує лише для того, щоб `generic` зʼявлявся на бічній панелі
поряд з іншими 89 продуктами.

```yaml
targets:
  - id: in-house-api
    product: generic
    address: https://internal.example.com
    parser:
      type: regex
      regex: 'v(\d+\.\d+\.\d+)'
```

## Автентифікація

Приймаються `none`, `bearer`, `token-header` і `basic` — усе, що насправді
очікує Ваш внутрішній сервіс.

## Зіставлення з CVE

Не зіставляється — написаний вручну парсер не має ідентичності продукту, за якою можна було б шукати CVE. Див. [Зіставлення з CVE](/uk/cve/#які-продукти-зіставляються).

## Резолвер життєвого циклу

Немає — ціль, налаштована вручну, за визначенням не має календаря для пошуку.
Не бачите свого продукту серед 89 окремих проб? Див.
[Підтримувані продукти](/uk/products/#не-знайшли-свій-продукт) — там описано два
шляхи: цей запасний вихід або запит на справжню пробу.
