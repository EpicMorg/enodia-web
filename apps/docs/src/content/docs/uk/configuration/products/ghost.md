Читає `GET /ghost/api/admin/site/` — єдиний ендпоінт Admin API, який Ghost
віддає без сеансу чи ключа (адмін-застосунок читає його ще до входу), — і
бере `site.version`. Схема за замовчуванням — `https`.

```yaml
targets:
  - id: ghost-main
    product: ghost
    address: https://blog.example.com
```

## Публічна лише major.minor

Підтверджено наживо на `ghost:6`: ендпоінт повідомив `6.69`, так само як
`<meta name="generator">` і заголовок `Content-Version`, тоді як
встановлений пакет мав версію 6.69.0. Повна версія доступна лише з ключем
Admin API, підписаним JWT, — новий вид облікових даних заради однієї цифри
того не вартий: релізи Ghost майже без винятків мають вигляд `x.y.0`, а
`6.69` під час порівняння дорівнює тегу `v6.69.0`.

## Автентифікація

Немає — ендпоінт публічний, і проба не приймає жодного виду облікових
даних. Починаючи з 2.2.0, облікові дані, привʼязані до цілі `ghost`, є
помилкою конфігурації, а не мовчки ігноруються — див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## Записувані поля

Лише `version` — major.minor, напр. `6.69`; ця проба не записує полів
`extra`.

## Зіставлення з CVE

Зіставляється з NVD і БДУ ФСТЕК, якщо налаштовано [блок `cve:`](/uk/cve/).

## Резолвер життєвого циклу

`github:TryGhost/Ghost` — endoflife.date не має календаря Ghost
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»).
