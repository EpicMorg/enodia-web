## Автентифікація — обовʼязкова

HTTP Basic auth; без неї точка входу відповідає `401` (підтверджено
наживо).

```yaml
credentials:
  ilo-ro:
    kind: basic
    username: enodia
    password: "${ILO_PASSWORD}"
```

Достатньо облікового запису iLO лише для читання. iLO зазвичай віддають
самопідписаний сертифікат — закріпіть його, а не вимикайте перевірку,
див. [Конфігурація → TLS](/uk/configuration/#tls-tls).

## Лише iLO 4

API iLO 4 називає себе «HP RESTful Root Service» — це API HP, старший за
Redfish, а не реалізація Redfish, — але саме цей ресурс збігається з
Redfish настільки, що читається так само. Ідентичність перевіряється за
ключем `Oem.Hp`. iLO 5 повністю сумісний із Redfish і, найімовірніше,
потребує іншої перевірки; жодного iLO 5 не було під рукою, щоб
підтвердити це наживо, тож проби для нього поки немає — замість
вгаданої.

## Записувані поля

- `version` — розібрана з `FirmwareVersion`: `iLO 4 v2.82` → `2.82`
- `extra.raw` — повний рядок `FirmwareVersion`

## Зіставлення з CVE

Зіставляється з NVD і БДУ ФСТЕК, якщо налаштовано [блок `cve:`](/uk/cve/). Починаючи з 2.2; версія прошивки
проби (`2.82`) порівнюється як є з діапазонами `integrated_lights-out_4`
у NVD і «HP iLO 4» у БДУ.

## Резолвер життєвого циклу

Немає — прошивки BMC не мають публічного календаря життєвого циклу
(підтверджено 404 під кожним випробуваним slug). Лише для інвентаризації.
