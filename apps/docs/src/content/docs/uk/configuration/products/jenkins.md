Читає версію із **заголовка відповіді `X-Jenkins`**, а не з тіла
відповіді — Jenkins встановлює цей заголовок у кожній відповіді, зокрема й у
`403` на неавтентифікований запит, тоді як тіло, яке повертається на
автентифікований запит, взагалі не містить поля з версією.

```yaml
targets:
  - id: jenkins-main
    product: jenkins
    address: https://jenkins.example.com
```

## Автентифікація

Необовʼязкова. Свіжий екземпляр зі стандартним security realm відповідає на
анонімний запит до `/api/json` кодом `403` — тут це не помилка, `X-Jenkins`
усе одно присутній у тій самій відповіді. Якщо Ви бажаєте автентифікуватися,
приймається Basic-автентифікація:

```yaml
credentials:
  jenkins-admin:
    kind: basic
    username: admin
    password: "${JENKINS_TOKEN}"
```

## Записувані поля

- `version` — із заголовка `X-Jenkins`
- `extra.mode`, `extra.useSecurity` — заповнюються лише тоді, коли запит був
  достатньо автентифікований, щоб отримати тіло з `200`; відсутні в разі
  анонімного `403`

## Зіставлення з CVE

Зіставляється з NVD і БДУ ФСТЕК, якщо налаштовано [блок `cve:`](/uk/cve/). Щотижневі (`2.580`) і LTS-релізи
(`2.568.3`) отримують те саме виправлення під різними номерами; починаючи
з 2.2, лінійку релізів визначає форма самої версії, тож виправлений LTS
більше не позначається щотижневим діапазоном того самого виправлення —
див. [Зіставлення з урахуванням редакції](/uk/cve/#зіставлення-з-урахуванням-редакції).
