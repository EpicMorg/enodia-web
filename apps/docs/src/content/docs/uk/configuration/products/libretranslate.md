Читає `GET /spec` — власний документ OpenAPI (Swagger 2.0) цього API,
публічний навіть там, де для перекладу потрібен ключ API. Схема за
замовчуванням — `https`.

```yaml
targets:
  - id: translate-main
    product: libretranslate
    address: https://translate.example.com
```

## Перевірка ідентичності вендора

`info.version` — версія сервера. Проба також вимагає, щоб `info.title`
дорівнював `"LibreTranslate"`, аби документ Swagger іншого сервісу не було
прочитано як документ LibreTranslate.

## Автентифікація

Немає — `/spec` публічний, і проба не приймає жодного виду облікових даних
(ключ API потрібен лише для перекладу, якого проба ніколи не виконує).
Починаючи з 2.2.0, облікові дані, налаштовані для цієї цілі, є помилкою
конфігурації, а не ігноруються; див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## Записувані поля

Лише `version` — напр. `1.9.6`, з `info.version` (підтверджено наживо на
`libretranslate/libretranslate:latest`, реліз v1.9.6). Ця проба не записує
полів `extra`.

## Зіставлення з CVE

Не зіставляється — жодна з баз не має придатних для цього даних. Див.
[Зіставлення з CVE](/uk/cve/#які-продукти-зіставляються).

## Резолвер життєвого циклу

`github:LibreTranslate/LibreTranslate` — endoflife.date не має календаря
LibreTranslate (підтверджено 404), тому резолвінг натомість виконується
через GitHub Releases: лише останній опублікований тег, що не є
пре-релізом, без дат eol/support/lts (GitHub не має позиції щодо політики
життєвого циклу, лише «який реліз останній»).
