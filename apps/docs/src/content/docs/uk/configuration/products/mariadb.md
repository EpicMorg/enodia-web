Сирий TCP-протокол, а не HTTP — `address` має вигляд `host` або
`host:port`, без схеми. Якщо порт не вказано, використовується `3306`.
Те саме рукостискання, що й у [MySQL](/uk/configuration/products/mysql/):
MariaDB сама повідомляє свою версію в початковому пакеті рукостискання,
до будь-якого кроку автентифікації, тож цій пробі ніколи не потрібні
облікові дані.

```yaml
targets:
  - id: mariadb-main
    product: mariadb
    address: db.example.com:3306
```

## Автентифікація

Немає — версія зчитується безпосередньо з рукостискання.

## Перевірка ідентичності вендора

MariaDB і MySQL говорять ідентичним рукостисканням і відрізняються лише
рядком версії, який має два вигляди, обидва підтверджені наживо:

- **MariaDB 10.x** приховує свою версію за префіксом сумісності `5.5.5-`
  для старих клієнтів MySQL: `5.5.5-10.11.19-MariaDB-ubu2204`. Префікс
  відкидається.
- **MariaDB 11.0+** відмовилася від префікса: `11.4.13-MariaDB-ubu2404`,
  `12.3.3-MariaDB-ubu2404`. Тоді єдина ознака — `-MariaDB` у версії.
  Розпізнається починаючи з 2.1.1 — 2.1.0 такі сервери відхиляла.

Приймається будь-який із двох виглядів. Спрямована на справжній сервер
MySQL, у версії якого немає ні того, ні іншого, проба завершується
помилкою, а не записує хибний факт, — дзеркальне відображення того, як
[`mysql`](/uk/configuration/products/mysql/#mariadb--інший-продукт)
відхиляє сервер MariaDB.

## Записувані поля

- `version` — числова версія, напр. `10.11.19`
- `extra.tag` — тег вендора після неї, напр. `MariaDB-ubu2204`, якщо є

## Зіставлення з CVE

Поки не зіставляється — MariaDB зʼявилася у 2.1, і upstream відклав її
зіставлення з CVE на пізніший, окремий прохід. Див.
[Зіставлення з CVE](/uk/cve/#які-продукти-зіставляються).
