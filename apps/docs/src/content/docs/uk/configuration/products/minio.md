SSH-проба: вона входить на хост і запускає власний `--version` бінарного
файлу сервера — спершу `minio` за назвою, потім `/usr/local/bin/minio`.
Якщо порт не вказано, використовується `22`, без схеми — той самий
механізм SSH, облікові дані та перевірка ключа хоста, що й у сімейства
[ідентифікації ОС через SSH](/uk/configuration/products/ssh-os-probes/).

```yaml
targets:
  - id: minio-01
    product: minio
    address: minio-01.example.com
    credentials: linux-host-ssh
```

## Чому SSH

MinIO не віддає версію анонімно на жодній мережевій поверхні: заголовок
`Server` в S3 API — просто `MinIO`, анонімний `/api/v1/login` консолі
повертає лише стратегію входу, а адмін-API та метрики Prometheus
потребують адмін-ключа або bearer-токена, згенерованого через `mc`.

## MinIO у контейнері

Якщо MinIO працює в Docker або Podman, а на самому хості бінарного файлу
немає, вкажіть контейнер в `options` — тоді команда виконується через
`docker exec` (або `podman exec`):

```yaml
targets:
  - id: minio-01
    product: minio
    address: minio-01.example.com
    credentials: linux-host-ssh
    options:
      container: minio               # назва контейнера
      container_runtime: podman      # необовʼязково: docker (за замовчуванням) або podman
```

Користувачеві SSH має бути дозволено використовувати це середовище
виконання. Назва контейнера перевіряється за власним шаблоном назв
Docker, перш ніж потрапити у віддалену команду.

## Назви релізів як версії

MinIO називає релізи за часовою позначкою UTC — `RELEASE.2025-10-15T17-29-55Z`
— і в `--version`, і у своїх тегах GitHub. enodia згортає таку назву, з
`_<MARKER>` після `RELEASE` чи без нього (внутрішні збірки мають вигляд
`RELEASE_INHOUSE.…`), у порівнянну форму `2025.10.15.17.29.55` — однаково
для спостереженої версії й для тегу резолвера.

## Автентифікація — обовʼязкова

Облікові дані SSH, `ssh-key` або `password` — див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## Записувані поля

- `version` — напр. `RELEASE_INHOUSE.2025-03-12T18-04-18Z`, з
  `minio version RELEASE_INHOUSE.2025-03-12T18-04-18Z (commit-id=…)`
- `extra.build` — маркер після `RELEASE_` у збірці не з апстриму,
  напр. `INHOUSE`
- `extra.commit` — `commit-id`, якщо є
- `extra.runtime` — середовище виконання Go з рядка `Runtime:`, напр.
  `go1.24.4`
- `extra.container` — назва контейнера, якщо задано `options.container`
- `extra.hostKeyVerified`

## Зіставлення з CVE

Зіставляється з NVD і БДУ ФСТЕК, якщо налаштовано [блок `cve:`](/uk/cve/).
Обидва джерела записують свої межі як часові позначки релізів
(`2025-10-15t17-29-55z`, у будь-якому регістрі), які згортаються в ту саму
форму з крапками, що й опитана версія, тож їх можна порівнювати; межа,
задана просто датою, і далі не розбирається.

## Резолвер життєвого циклу

`github:minio/minio` — endoflife.date не має сторінки MinIO (підтверджено
404), тому резолвінг натомість виконується через GitHub Releases: лише
останній опублікований тег, що не є пре-релізом, без дат eol/support/lts.
Репозиторій архівовано: останній реліз community-редакції —
`RELEASE.2025-10-15T17-29-55Z`, і відтепер саме з ним порівнюється будь-який
MinIO.
