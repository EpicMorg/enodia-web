Сирий TCP-протокол, а не HTTP — `address` має вигляд `host` або
`host:port`, без схеми `https://`/`http://` (тут немає про що попереджати
через відсутню схему; див. [Конфігурація](/uk/configuration/#targets)).
Якщо порт не вказано, використовується `3306`.

Жоден запит не надсилається: MySQL сама повідомляє свою версію в
початковому пакеті рукостискання, до будь-якого кроку автентифікації, —
тож цій пробі ніколи не потрібні облікові дані, щоб її побачити.

```yaml
targets:
  - id: mysql-main
    product: mysql
    address: db.example.com:3306
```

## Автентифікація

Немає — версія зчитується безпосередньо з рукостискання, ще до моменту,
коли облікові дані взагалі мали б значення.

## MariaDB — інший продукт

MariaDB видає себе версією в рукостисканні: MariaDB 10.x приховує її за
префіксом `5.5.5-` для старих клієнтів MySQL
(`5.5.5-10.11.19-MariaDB-ubu2204`), а MariaDB 11.0+ надсилає її без
префікса, але з позначкою (`11.4.13-MariaDB-ubu2404`). `product: mysql`,
спрямований на сервер MariaDB, розпізнає обидва вигляди й **навмисно
завершується помилкою**, називаючи в повідомленні справжню версію
MariaDB, замість того щоб мовчки записати її як факт про MySQL.
Починаючи з 2.1, MariaDB має власну пробу — використовуйте для неї
[`product: mariadb`](/uk/configuration/products/mariadb/).

:::caution[MariaDB 11.0+ до 2.1.1]
До 2.1.0 включно розпізнавався лише префікс `5.5.5-`, тож сервер
MariaDB 11.0+ за ціллю `product: mysql` записувався **як MySQL** і
звірявся з життєвим циклом MySQL. Починаючи з 2.1.1 така ціль натомість
завершується помилкою — переключіть її на `product: mariadb`.
:::
