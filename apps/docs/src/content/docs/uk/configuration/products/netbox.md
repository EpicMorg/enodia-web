Читає анонімну сторінку входу, `GET /login/`, кореневий елемент якої
містить `data-netbox-version` — напр. `4.3.3-Docker-3.3.0` у NetBox,
запущеному з netbox-docker. Якщо атрибута немає, натомість
використовується версія, з якою сторінка завантажує свій бандл
(`/static/netbox.js?v=4.3.3`). Схема за замовчуванням — `https`.

```yaml
targets:
  - id: netbox-main
    product: netbox
    address: https://netbox.example.com
```

## Чому сторінка входу

REST API NetBox (`/api/status/`) потребує токена; сторінка входу містить
версію без нього (підтверджено наживо на продакшн-екземплярі NetBox з
netbox-docker). Частина до `-Docker-` — власна версія NetBox; решта —
версія образу netbox-docker.

## Автентифікація

Немає — сторінка входу публічна, і проба не приймає жодного виду
облікових даних. Починаючи з 2.2.0, облікові дані, привʼязані до цілі
`netbox`, є помилкою конфігурації, а не мовчки ігноруються — див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## Записувані поля

- `version` — версія NetBox, напр. `4.3.3`
- `extra.netboxDocker` — версія образу netbox-docker (`3.3.0`), лише якщо
  `data-netbox-version` має суфікс `-Docker-`

## Зіставлення з CVE

Зіставляється з NVD, якщо налаштовано [блок `cve:`](/uk/cve/).
«LenelS2 NetBox» у БДУ — інший продукт, і він не використовується.

## Резолвер життєвого циклу

`github:netbox-community/netbox` — endoflife.date не має календаря NetBox
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»).
