Читає `GET /api/v1/info` агента, який за замовчуванням віддається без
входу в систему. Схема за замовчуванням — `https`.

```yaml
targets:
  - id: netdata-01
    product: netdata
    address: https://netdata-01.example.com
```

## Що читається

Відповідь починається з `"version": "v2.12.1"`, поруч — `release-channel`.
Решта описує хост — uid, ядро, мітки, обладнання, хмару, — ніщо з цього не
описує саме програмне забезпечення, тому читаються лише версія та канал
релізів. Відповідь без `version` позначається як «не підтримується» (це не
Netdata).

## Автентифікація

Необовʼязкова — за замовчуванням агент відповідає анонімно. `basic` або
`bearer`, якщо налаштовані, передаються далі — для агента за проксі, який
їх вимагає; починаючи з 2.2.0, будь-який інший вид є помилкою
конфігурації. Див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

```yaml
credentials:
  netdata-proxy:
    kind: basic
    username: enodia
    password: "${NETDATA_PROXY_PASSWORD}"
```

## Записувані поля

- `version` — так, як її повідомляє агент, напр. `v2.12.1` (підтверджено
  наживо на `netdata/netdata:stable`)
- `extra.releaseChannel` — напр. `stable` або `nightly`, якщо є

## Зіставлення з CVE

Зіставляється з NVD і БДУ ФСТЕК, якщо налаштовано [блок `cve:`](/uk/cve/).

## Резолвер життєвого циклу

`github:netdata/netdata` — endoflife.date не має календаря Netdata
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»).
