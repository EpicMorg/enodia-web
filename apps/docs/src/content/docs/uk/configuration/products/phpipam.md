Анонімно читає сторінку входу, `GET /index.php?page=login`. Схема за
замовчуванням — `https`.

```yaml
targets:
  - id: ipam-main
    product: phpipam
    address: https://ipam.example.com
```

## Звідки береться версія

Нижній колонтитул сторінки входу містить `phpIPAM IP address management [v1.8.3]`,
а кожна таблиця стилів і кожен скрипт на ній завантажуються з
`?v=1.8.3_r002_v46` — власним префіксом скриптів phpIPAM: видима версія,
ревізія коду та версія схеми бази даних. Версію дає нижній колонтитул;
суфікс ресурсів — запасний варіант, якщо колонтитул прибрано
налаштуваннями, і джерело ревізії та версії схеми. Старіші релізи
завантажують ресурси з простим `?v=1.7.3` (помічено на продакшн-екземплярі
1.7.3), без частин ревізії та схеми — версія все одно читається, а два
поля `extra` тоді відсутні. Сторінка без жодного з них позначається як
«не підтримується».

## Автентифікація

Немає — проба читає анонімну сторінку й не приймає жодного виду облікових
даних. Починаючи з 2.2.0, облікові дані, налаштовані для цієї цілі, є
помилкою конфігурації, а не ігноруються; див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## Записувані поля

- `version` — напр. `1.8.3`, з `phpIPAM IP address management [v1.8.3]`
  (підтверджено наживо на `phpipam/phpipam-www:latest`)
- `extra.revision` — ревізія коду із суфікса ресурсів, напр. `002`
- `extra.dbVersion` — версія схеми бази даних із суфікса ресурсів,
  напр. `46`

## Зіставлення з CVE

Зіставляється з NVD і БДУ ФСТЕК, якщо налаштовано [блок `cve:`](/uk/cve/).

## Резолвер життєвого циклу

`github:phpipam/phpipam` — endoflife.date не має календаря phpIPAM
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»).
