Читає анонімну сторінку входу самостійно розгорнутого Sentry,
`GET /auth/login/` (яка перенаправляє на сторінку входу єдиної
організації). Кожна сторінка містить `window.__initialData = {...}`, і його
`version.current` є версією. Схема за замовчуванням — `https`.

```yaml
targets:
  - id: sentry-main
    product: sentry
    address: https://sentry.example.com
```

## Чому сторінка входу

Підтверджено наживо, анонімно, на самостійно розгорнутому
продакшн-екземплярі 26.2.1. Той самий обʼєкт `version` має також поле
`latest` — власну перевірку оновлень Sentry, — яке **не** використовується:
з вимкненою перевіркою воно було застарілим (`21.7.0`). Корінь API
`/api/0/` теж анонімний, але його `"version": "0"` — версія API, а не
сервера; `/api/0/internal/health/` потребує автентифікації.

## Автентифікація

Немає — сторінка входу публічна, і проба не приймає жодного виду
облікових даних. Починаючи з 2.2.0, облікові дані, привʼязані до цілі
`sentry`, є помилкою конфігурації, а не мовчки ігноруються — див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## Записувані поля

- `version` — з `version.current`, напр. `26.2.1`
- `extra.build` — git-коміт із `version.build`
- `extra.mode` — `sentryMode`, напр. `SELF_HOSTED`

## Зіставлення з CVE

Зіставляється з NVD, якщо налаштовано [блок `cve:`](/uk/cve/).
Записи «Sentry» у БДУ стосуються SDK, а не сервера, і не використовуються.

## Резолвер життєвого циклу

`github:getsentry/self-hosted` — endoflife.date не має календаря Sentry
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»). Теги релізів getsentry/self-hosted (`26.8.0`,
`26.9.0`, …) — це версії сервера, які він встановлює.
