Читає `GET /redfish/v1/Managers/1` — власний ресурс Redfish manager
контролера BMC, — щоб отримати версію прошивки.

```yaml
targets:
  - id: srv125-bmc
    product: supermicro-bmc
    address: https://bmc-srv125.example.com
    credentials: bmc-admin
```

## Автентифікація — обовʼязкова

HTTP Basic auth; без неї точка входу відповідає `401` (підтверджено
наживо).

```yaml
credentials:
  bmc-admin:
    kind: basic
    username: ADMIN
    password: "${BMC_PASSWORD}"
```

Достатньо облікового запису BMC лише для читання. BMC зазвичай віддають
самопідписаний сертифікат — закріпіть його, а не вимикайте перевірку,
див. [Конфігурація → TLS](/uk/configuration/#tls-tls).

## Перевірка ідентичності вендора

Підтверджено наживо на двох поколіннях — платі серії X12 (AST2600,
прошивка `01.05.25`) і старішій платі епохи X9/X10 (прошивка
`01.73.13`). Жодна з них не містить поля виробника, яке ця проба могла б
отримати одним запитом, але обидві містять ключ `Oem.Supermicro` саме в
цьому ресурсі, тож перевіряється саме він. BMC іншого вендора, що
відповідає за тим самим шляхом, завершується помилкою, а не записується
як Supermicro.

- `version` — `FirmwareVersion`, напр. `01.05.25`
- `extra.model`, якщо є

## Зіставлення з CVE

Поки не зіставляється — BMC-проби зʼявилися у 2.1, і upstream відклав
їхнє зіставлення з CVE на пізніший, окремий прохід. Див.
[Зіставлення з CVE](/uk/cve/#які-продукти-зіставляються).

## Резолвер життєвого циклу

Немає — прошивки BMC не мають публічного календаря життєвого циклу
(підтверджено 404 під кожним випробуваним slug). Лише для інвентаризації.
