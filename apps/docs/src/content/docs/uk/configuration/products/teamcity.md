Читає версію анонімно з `GET /app/rest/server/version`, якщо облікові
дані не налаштовано, або з `GET /app/rest/server` — точки входу, на яку
насамперед вказує власний довідник REST API TeamCity, — якщо налаштовано
токен.

```yaml
targets:
  - id: teamcity-main
    product: teamcity
    address: https://teamcity.example.com
    # credentials: teamcity-pat    # необовʼязково, див. нижче
```

## Автентифікація — необовʼязкова, і тут легко все переплутати, якщо її додати

**Облікові дані не потрібні.** TeamCity віддає
`/app/rest/server/version` будь-кому, простим текстом — `2026.1.1 (build
222577)` — навіть із вимкненим гостьовим входом. Підтверджено на свіжих
серверах від 2017.2 до 2026.1 без створеного адміністратора та на семи
продакшн-екземплярах (від 2024.03 до 2026.1.3) без облікових даних. Це
не гостьовий доступ: `/app/rest/server` і ендпоінти лише для гостей на
тих самих серверах відхиляються. Поки TeamCity запускається, він
відповідає на будь-який шлях HTML-сторінкою обслуговування з кодом 200,
тому відповідь має повністю відповідати `YYYY.N[.N] (build N)`, інакше
ціль завершується помилкою як нерозбірна.

**Якщо налаштовано токен**, проба натомість читає `/app/rest/server` —
Ви попросили автентифіковане читання, ця відповідь містить ще й
`internalId`, а хибний токен лишається видимою помилкою автентифікації,
а не маскується анонімним шляхом. `/app/rest/server` ніколи не буває
анонімним: свіжий екземпляр відповідає `401` з викликами і Basic, і
Bearer. TeamCity має **два різні види токенів, підтверджено наживо, які
працюють лише як протилежні види облікових даних**:

- Одноразовий **bootstrap-токен суперкористувача**, який свіжий сервер
  виводить у лог під час першого запуску, працює лише як **Basic** —
  порожнє імʼя користувача, токен як пароль. Надісланий як простий
  `Authorization: Bearer`, він відхиляється.
- **Персональний токен доступу** звичайного користувача (Profile →
  Access Tokens — саме так автентифікується справжня довготривала
  автоматизація) — навпаки: перевірено на семи реальних продакшн-екземплярах,
  він працює як **Bearer** і безумовно відхиляється як Basic («Incorrect
  username or password», навіть із порожнім імʼям користувача).

```yaml
credentials:
  # bootstrap-токен — Basic, порожнє імʼя користувача
  teamcity-bootstrap:
    kind: basic
    username: ""
    password: "${TEAMCITY_BOOTSTRAP_TOKEN}"

  # персональний токен доступу — Bearer
  teamcity-pat:
    kind: bearer
    value: "${TEAMCITY_TOKEN}"
```

У будь-якій довготривалій конфігурації використовуйте персональний токен
доступу — bootstrap-токен призначений для заміни після першого входу.

## Записувані поля

- `version` — повний рядок, напр. `2026.2 (build 238924)`
- `extra.buildNumber`
- `extra.internalId` — лише з токеном (`/app/rest/server`)
