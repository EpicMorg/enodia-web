Читає `GET /echo`, на який TorrServer відповідає своєю версією простим
текстом. Схема за замовчуванням — `https`.

```yaml
targets:
  - id: torrserver-main
    product: torrserver
    address: https://torrserver.example.com
```

## Вигляд версії

`/echo` відповідає, напр., `MatriX.146` — кодова назва й номер, так само
як у тегах релізів TorrServer на GitHub (`MatriX.146`, `MatriX.145.2`).
Версія записується як є; порівняння використовує числа після кодової
назви, з обох боків. Відповідь іншого вигляду (скажімо, HTML-сторінка)
позначається як «не підтримується».

## Автентифікація

Необовʼязкова. `basic` надсилається, якщо налаштовано, — для екземпляра з
увімкненою власною автентифікацією; якщо нічого не налаштовано, запит
анонімний. `basic` — єдиний вид, що приймається; починаючи з 2.2.0,
будь-який інший вид є помилкою конфігурації. Див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

```yaml
credentials:
  torrserver-auth:
    kind: basic
    username: admin
    password: "${TORRSERVER_PASSWORD}"
```

## Записувані поля

Лише `version` — напр. `MatriX.146` (саме це відповів живий
`ghcr.io/yourok/torrserver:latest` на `/echo`). Ця проба не записує полів
`extra`.

## Зіставлення з CVE

Не зіставляється — жодна з баз не має придатних для цього даних. Див.
[Зіставлення з CVE](/uk/cve/#які-продукти-зіставляються).

## Резолвер життєвого циклу

`github:YouROK/TorrServer` — endoflife.date не має календаря TorrServer
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»).
