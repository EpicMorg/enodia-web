Входить через власний socket.io API Uptime Kuma й читає версію з події
`info`, яку сервер надсилає після входу.

```yaml
targets:
  - id: uptime-kuma-main
    product: uptime-kuma
    address: https://uptime-kuma.example.com
    credentials: kuma-monitor
```

## Чому потрібен вхід

Жоден анонімний ресурс не містить версії. Подія `info` сервера її містить,
але нове зʼєднання отримує цю подію без версії, доки сокет не увійде в
систему. `/metrics` не має серії з версією, а ключі API відкривають лише
`/metrics`. Підтверджено наживо на 1.23.17 і 2.5.5, а також на публічній
сторінці статусу продакшн-екземпляра, чиї `/api/status-page/*` і сокет теж
її не містять.

Тому проба говорить рівно стільки транспорту HTTP long-polling Engine.IO
v4 (`/socket.io/?EIO=4&transport=polling`), скільки потрібно, щоб відкрити
сеанс, надіслати `login` і опитувати, доки не надійде подія `info` з
`version`, — а потім відʼєднується. 1.23.17 надсилає `info` з версією після
підтвердження входу, 2.5.5 — до нього; обидва порядки обробляються.

## Автентифікація — обовʼязкова

Імʼя користувача та пароль, `kind: password`:

```yaml
credentials:
  kuma-monitor:
    kind: password
    username: monitor
    password: "${UPTIME_KUMA_PASSWORD}"
```

Приймається лише `password`; будь-який інший вид є помилкою конфігурації.
Див. [Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

- Відхилений вхід — це помилка автентифікації з власним повідомленням
  Uptime Kuma (`Incorrect username or password.`).
- **Користувач із 2FA не може увійти таким способом** — підтвердження
  входу вимагає токен. Про це повідомляється, а не обходиться:
  використовуйте користувача для моніторингу без 2FA.
- Uptime Kuma обмежує частоту входів: запуск одразу після кількох хибних
  паролів одного разу не вдався на 2.5.5, а всі наступні запуски пройшли.
- Uptime Kuma через звичайний HTTP потребує `allow_insecure_transport`, як
  і будь-які облікові дані, — див.
  [Спершу HTTPS](/uk/concepts/#спершу-https-облікові-дані-за-замовчуванням-ніколи-не-передаються-відкритим-текстом).

## Записувані поля

- `version` — напр. `2.5.5`
- `extra.latestVersion` — власна перевірка оновлень Uptime Kuma, напр. `2.5.5`
- `extra.dbType` — напр. `sqlite`

## Зіставлення з CVE

Зіставляється з NVD, якщо налаштовано [блок `cve:`](/uk/cve/).
