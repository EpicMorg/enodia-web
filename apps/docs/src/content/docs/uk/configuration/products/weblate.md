Анонімно читає `GET /about/`. Схема за замовчуванням — `https`.

```yaml
targets:
  - id: weblate-main
    product: weblate
    address: https://weblate.example.com
```

## Звідки береться версія

Нижній колонтитул кожної сторінки Weblate містить `Powered by <a href="https://weblate.org/">Weblate 2026.10</a>`,
а його посилання на документацію веде на `docs.weblate.org/en/weblate-2026.10/`.
Проба спершу читає колонтитул, а посилання на документацію — якщо
колонтитул прибрано налаштуваннями; сторінка без жодного з них
позначається як «не підтримується». Читається `/about/`, бо він існує в
кожному Weblate; сайт із `REQUIRE_LOGIN` перенаправляє його на сторінку
входу, яка має той самий колонтитул. Корінь REST API (`/api/`) теж
анонімний, але не містить версії, а `/api/metrics/` потребує токена.

Після 5.x Weblate перейшов на календарні версії (`2026.9`, `2026.9.1`,
`2026.10`); розбираються обидва вигляди.

## Автентифікація

Немає — проба читає анонімну сторінку й не приймає жодного виду облікових
даних. Починаючи з 2.2.0, облікові дані, налаштовані для цієї цілі, є
помилкою конфігурації, а не ігноруються; див.
[Конфігурація → Облікові дані](/uk/configuration/#облікові-дані).

## Записувані поля

Лише `version` — напр. `2026.10` (підтверджено наживо на
`weblate/weblate:latest`). Ця проба не записує полів `extra`.

## Зіставлення з CVE

Зіставляється з NVD, якщо налаштовано [блок `cve:`](/uk/cve/).

## Резолвер життєвого циклу

`github:WeblateOrg/weblate` — endoflife.date не має календаря Weblate
(підтверджено 404), тому резолвінг натомість виконується через GitHub
Releases: лише останній опублікований тег, що не є пре-релізом, без дат
eol/support/lts (GitHub не має позиції щодо політики життєвого циклу, лише
«який реліз останній»). Weblate позначає свої релізи тегами
`weblate-2026.10`; починаючи з 2.2.0, резолвер відкидає початкове
`<repo>-` або `<repo>_` з тегів релізів, тож LATEST і CYCLE показують
`2026.10`.
