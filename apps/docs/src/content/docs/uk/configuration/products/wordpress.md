Послідовно пробує дві анонімні поверхні й використовує ту, що відповість
першою:

1. Власний рядок `<generator>` RSS-стрічки (`/?feed=rss2` — форма з
   рядком запиту, яка працює незалежно від того, чи налаштовано «красиві»
   постійні посилання).
2. Тег `<meta name="generator" content="WordPress X.Y.Z" />` головної
   сторінки (`/`).

```yaml
targets:
  - id: wordpress-main
    product: wordpress
    address: https://blog.example.com
```

## Автентифікація

Немає — ендпоінт не приймає жодного виду облікових даних.

## Чому спершу пробується стрічка

Стрічка переживає найпоширеніший крок посилення захисту: WordPress
реєструє свій тег generator на хуках стрічки окремо від власної дії
`wp_head` головної сторінки, тому однорядковий фрагмент
`remove_action('wp_head', 'wp_generator')`, який дає кожен посібник на
кшталт «приховайте версію WordPress», прибирає лише тег головної сторінки,
а не стрічки — підтверджено читанням власних реєстрацій хуків WordPress,
а не припущено. Сайт, який пішов далі й повністю вимкнув стрічки або
прибрав обидві ознаки, отримує зрозумілу помилку «not supported».

## Записувані поля

Лише `version` — ця проба не записує полів `extra`.

## Зіставлення з CVE

Зіставляється з NVD і БДУ ФСТЕК, якщо налаштовано [блок `cve:`](/uk/cve/).

## Резолвер життєвого циклу

`endoflife:wordpress`.
