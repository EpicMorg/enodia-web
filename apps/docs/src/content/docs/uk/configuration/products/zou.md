Читає версію з `GET /api/status` — справжнього API-бекенду стека
відстеження виробництва CG-Wire, більш відомого під брендом
[Kitsu](/uk/configuration/products/kitsu/) — його фронтендом на Vue.js,
який не має власного ендпоінта версії.

```yaml
targets:
  - id: zou-main
    product: zou
    address: https://kitsu.example.com
```

## Автентифікація

Немає — ендпоінт не приймає жодного виду облікових даних.

## Перевірка ідентичності вендора

Поле `name` у відповіді порівнюється з `"Zou"` — з тієї ж причини, що й у
проб Atlassian і Jellyfin: явна назва продукту в конфігурації має виявляти
URL, спрямований не на той сервіс.

## `zou` чи `kitsu` — та сама проба, різні резолвери, не псевдонім

`product: kitsu` звертається до ідентичного ендпоінта й реалізації проби —
на [його власній сторінці](/uk/configuration/products/kitsu/) пояснено,
чому ці два продукти зареєстровано окремо, а не як один продукт із
псевдонімом: власний GitHub-репозиторій `zou` не публікує придатних Releases
(лише голі git-теги, підтверджено наживо), тому `product: zou` лишається без
резолвера, щоб не ризикувати порівнянням із номерами версій іншого компонента.

## Записувані поля

- `version`
- `extra.databaseUp`, `extra.keyValueStoreUp`, `extra.eventStreamUp`,
  `extra.jobQueueUp`, `extra.indexerUp` — прапорці стану компонентів,
  `"true"`/`"false"`

## Зіставлення з CVE

Не зіставляється — жодна з баз не має придатних для цього даних. Див. [Зіставлення з CVE](/uk/cve/#які-продукти-зіставляються).

## Резолвер життєвого циклу

Немає — GitHub-репозиторій `cgwire/zou` не має придатних Releases для
резолвінгу (підтверджено наживо: його Releases API повертає порожній
список — лише голі git-теги). Якщо Ви вважаєте, що у Вас «працює Kitsu»,
а не «працює Zou», `product: kitsu` натомість дає справжній резолвер за
`cgwire/kitsu`, спрямований на цей самий бекенд.
